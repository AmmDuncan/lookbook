Re-skinning Lookbook

A contract, not a skin.

Token names and semantic roles are the constant. Token values — accent hue, neutral temperature, type family, radius personality, shadow softness, density — are meant to be swapped per project. Components reference var(--…) only; never a literal hex, px, or radius. A new project keeps the structure, states, and rules — and gets a distinct look from fresh values, sharing the same DNA and quality bar.

05b — Font pairings

Font pairings #pairings

Typeface is a re-skin dial. The scale, weights, and tracking stay constant; only the --font-display and --font-sans values change per project. Six curated pairings below — drop one into :root and the whole system shifts personality.

Neutral product
safe default
Make the right thing easy.

A neutral grotesk for both display and body. Reads as quiet and confident at every size — the pairing every product can run for years without it feeling dated.

Pairing rules read once, follow always

Contrast by role, not chaos

Pair fonts that play different ROLES — a display face vs. a body face. Two similar grotesks fighting on the same page reads as a mistake, not a system.

Max 2 families + mono

One display, one body, one mono. Past three families the system loses coherence and the extra HTTP weight stops being worth it.

Compatible x-heights

Pair faces with similar x-height so 14 px body and 14 px overline don't look like different sizes when they sit next to each other.

Weight strategy

Display heavier (600–800) to do the lifting; body regular (400) for legibility. Skip bold body — that's the display face's job.

When to go expressive

Marketing pages, heroes, brand moments. Stay neutral for data-dense surfaces — admin, forms, tables. Never an expressive display face on a settings page.

Performance + fallbacks

Always include a system fallback stack and font-display: swap. Prefer variable fonts (one file, many weights). Each extra family is a real cost — budget it.

Typography re-skin contract

Change the families, keep the system.

A project picks a pairing by overriding ONLY --font-display / --font-sans (and optionally --font-mono) in :root. The scale, weights, tracking, and line-heights are structural constants — they don't move. Fonts become another re-skin dial alongside the accent color and radius personality. 

/* Per-project skin: override only the families. */
:root {
  --font-display: "Fraunces", Georgia, serif;
  --font-sans:    "Plus Jakarta Sans", ui-sans-serif, system-ui, sans-serif;
  --font-mono:    "JetBrains Mono", ui-monospace, monospace;
}

/* Structural \u2014 do NOT change per project. */
--text-h1-size, --text-h1-weight, --text-h1-track
--text-body-size, --text-body-lh
