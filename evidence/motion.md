# Evidence — Motion (P-MT calibration)

## Why this evidence file is different (read first)
The other patterns (detail, marketing, dashboard, auth…) are **reference-calibrated**: I studied real still screenshots and read *how the rules are applied* to confirm/calibrate/break each calibration. **Motion cannot be calibrated that way.** A still screenshot captures zero frames of an animation — you cannot read a duration, an easing curve, a stagger step, or a reduced-motion fallback from a single image. Watching app recordings would help but isn't reproducible the way a captured screenshot is, and it still wouldn't yield the *numbers* (ms, beziers) the pattern needs.

So motion is calibrated from the **established motion-design canon** — the same body of work the platform vendors and the WCAG group codified — and the timing psychophysics already baked into `fundamentals.md` F29. The receipts here are **principles + token tables from authoritative sources**, not screenshots. This is stated plainly so a future reader doesn't go looking for a reference study that can't exist.

## Calibration sources

|---|---|---|

## The calibration each source produced
1. **Material's emphasized vs standard easing** → two named enter/in-place tokens instead of a single "ease-out", and the rule that attached overlays grow *from the trigger* (transform-origin), not from center (P-MT-03). Material's duration tiers confirmed F29's band and set the per-element numbers (modal 220–260, popover 120–180, toast 200–240).
2. **Apple's "motion communicates"** → the surface-intent thesis: motion exists to answer *where from / what happened / what's the system doing*. Motion that answers none = texture-in-time, deletable by F35's logic. Also fixed enter-from-anchor as the directional rule.
3. **Disney slow-in/slow-out, used sparingly** → F30's no-linear rule, the press-dip and signature-settle as the *deliberate exceptions*, and the repeated "sparingly / one moment per view" guardrail so anticipation/follow-through don't bloat into cartoon UI.
4. **WCAG reduced-motion** → P-MT-10 made **mandatory on every recipe** and placed in Tier 1 (never yields). A recipe without a stated fallback is unfinished, exactly as a data view without an empty state is unfinished (F33).
5. **F36 texture-gating, applied to time** → motion expressiveness is **density-gated**: dense surfaces get functional motion only; spacious surfaces earn scroll reveals and a signature. This is the structural parallel that makes motion a first-class cross-cutting pattern rather than a loose list of timings.

## What this evidence does and does not establish
- **Establishes:** the *numbers* (durations, easing curves, stagger steps, thresholds) are not invented — they trace to Material/Apple tokens and the F29 psychophysical band; the *fallback* requirement traces to WCAG; the *restraint/gating* traces to Apple HIG + F36's logic.
- **Does NOT establish (honest limit):** that any specific real app uses these exact values — stills can't show that. The frame-sampling verification (below) proves a recipe *progresses correctly* (off → partial → settled) and that the easing reads right at sampled offsets; it does **not** prove perceived smoothness, frame rate, or how it feels in the hand. A real moving capture (Claude-in-Chrome GIF) is the only thing that closes that gap, and the main agent captures one.

## Verification — frame-sampling (the reproducible part)
Built `tmp/motion-verify.html`: six load-triggered `@keyframes` recipes (modal slide+fade 250ms ease-out, toast slide-in 220ms, 4-item list stagger 200ms/40ms-step, button press-dip, skeleton shimmer loop, signature settle 280ms), each labeled with its spec, all using `animation-fill-mode: backwards` so the start state holds at t=0, plus a `@media (prefers-reduced-motion: reduce)` block that neutralizes transforms/loops to a single fade. Frames sampled headless at `--virtual-time-budget` = 0 / 120 / 250 / 400ms; the renderer advances virtual time before each screenshot, so the four PNGs show the animations off → partial → settled. Contrast on all text pairs run through `scripts/contrast.mjs` — all PASS. Frame-sampling proves **progression + easing shape**; it cannot prove perceived smoothness (that's the GIF's job).
