01 — When to use what

Decision rules #decisions

Pick the lowest-impact pattern that solves the problem. Reach for heavier patterns (modal, full page) only when the lighter ones can't.

Overlaysleast → most disruptive
Tooltip.tooltip
Label-only hint for a control. One short line, no interactive content inside.
Any content the user might want to copy, click, or focus.
Popover.popover
Small contextual UI — a quick form, a single setting, related links.
Multi-step flows or anything wider than ~280 px.
Dropdown menu.menu
Picking an action from a fixed list of 3–10 items.
More than ~10 items — use a search field or command palette.
Drawer.drawer
Detail / edit view that should keep the parent visible. Comfortable for 1–3 fields with prose.
Pure confirmations (use modal) or hidden-from-context workflows (use a page).
Modal / Dialog.modal
Single, blocking decision: confirm a destructive action, or capture 1–6 fields the user must finish.
Anything skippable, exploratory, or with side scrolling. Never stack modals.
Full page/route
Multi-step flows, deeply linkable content, anything the user might bookmark or share.
Quick edits that yank the user out of context.
Data displaystructured → scannable
Data table.tbl
5+ items with comparable columns (status, owner, date) and bulk actions.
Mobile-primary surfaces and items where columns are mostly empty.
Card grid.card grid
Items with rich media or unequal hierarchy. Browsing, gallery, showcase.
When the user needs to sort / filter / select multiple at once.
Listvertical row stack
Many items, low column count, mobile-first surfaces.
When users need to compare values across items.
Messagesscope → persistence
Inline field error.field-error
Validation tied to a specific input. Bound via aria-describedby + aria-invalid.
System-level problems (use banner) or transient updates (use toast).
Toast.toast
Transient feedback after an action — saved, sent, copied. Auto-dismiss in 4–7 s.
Anything the user MUST read (use banner / modal) or critical errors.
Inline banner.alert
Persistent context-scoped message: billing on hold, sync failed, info to remember.
Decoration. Don't stack 3 alerts at the top of every page.
Navigationwithin page → across product
Tabs.tabs--underline / .tabs--pill
2–5 sibling views of the same resource. URLs may not change.
When views differ significantly in shape, or have separate URLs you want to share.
Separate pages/routes
Distinct workflows · permalink-worthy · 6+ siblings · ownership boundaries.
When the user wants to toggle quickly back and forth between views.
02 — Spacing & sizing

Spacing & sizing rules #spacing

Two clocks: inside a component (small, 4–12 px) and between sections (large, 32–96 px). Don't mix them.

Inside-component--space-1 → --space-6
Icon ↔ label--space-2 (8)
Inside a button, menu item, breadcrumb, badge.
Different gaps for different controls — keep one rhythm.
Field ↔ label / helper--space-1-5 (6)
Label → input → helper / error vertical stack.
Tight 4 px (cramped) or generous 16 px (loose) — 6 is the sweet spot.
Card padding--space-4 to --space-6 (16–24)
Card header / body / footer; modal body; popover body.
Padding smaller than 16 — cards lose definition.
Toolbar gap--space-2 (8)
Button groups, action rows, segmented controls.
No gap (controls touch) or 16 (looks disorganized).
Between sections--space-8 → --space-24
Section vertical rhythm--space-12 to --space-24 (48–96)
Marketing pages, dashboards, anywhere with clear section boundaries.
Tight section gaps — large sections need real breathing room.
Page top padding--space-10 (40)
First section under any sticky header.
Sticking content tight to the top bar.
Page-container width~1200 / 1400 max
Wide content: dashboards, settings, tables.
Stretching prose past ~720 px — readability collapses.
Control sizing--size-*-h
Default control height--size-md-h · 36 px desktop
Buttons, inputs, selects, steppers inside product UI.
Mixing heights in a single row — atoms share a height ladder, use it.
Touch target floor44 px · auto on coarse pointer
Any tappable target on a touch device. md auto-promotes — no opt-in needed.
Manually re-sizing controls for mobile. The media query handles it.
Dense rows--size-sm-h · 28 px
Tables, lists, sidebars — surfaces that benefit from density.
Primary actions and forms — too small to feel pressable.
03 — Accessibility

The non-negotiables #a11y

Hard requirements. If a component you build can't pass these, it's not done.

  1. Visible focus ring on every interactive element
    :focus-visible renders a 2 px outline at --focus-ring with 2 px offset. Never set outline: none without replacing it.
    --focus-ring
  2. 4.5:1 contrast for body text · 3:1 for ≥18 px or bold
    All semantic --text-* tokens meet this in both themes. If you introduce a new color, verify with an oklch contrast check.
    --text-* · --border-strong
  3. Every input has a label
    Visible <label for> preferred. aria-label only for icon-only controls. Placeholder is not a label.
    .field-label
  4. Errors announced via aria-invalid + aria-describedby
    Validation messages bound to the input with aria-describedby; input flagged with aria-invalid="true". Visible icon + text — never color alone.
    .field-error
  5. Full keyboard operability
    Tab order matches visual order. Esc closes overlays. Arrow keys traverse tablists / menus / option lists. Enter activates the focused control.
    tabindex · roles
  6. Roles + labels on every overlay
    Modals: role="dialog" aria-modal="true" aria-labelledby. Toasts: role="status" or role="alert" for errors. Menus: role="menu" with role="menuitem" children.
    role · aria-*
  7. Focus trapped in modals · restored on close
    When a modal opens, focus moves to its primary action or first input. When it closes, focus returns to the trigger.
    .modal · .drawer
  8. Respect prefers-reduced-motion
    All transforms / animations disabled under @media (prefers-reduced-motion: reduce). Replace motion with instant state change, never remove the affordance.
    --duration-* · --ease-*
  9. Live regions on async updates
    Toast container carries aria-live="polite" (status updates) or aria-live="assertive" + role="alert" for errors. Inline counters that change without a page navigation wrap their text in a polite live region too.
    aria-live · role="alert"
  10. Color is never the only signal
    Status badges carry an icon or dot in addition to color. Error inputs carry a message + icon, not just a red border. Critical for color-blind users and printed views.
    .badge-dot · .alert-icon
04 — Responsive

Responsive rules #responsive

Mobile-first. Each breakpoint adds capability; nothing critical hides forever.

Breakpoint behavior--bp-sm 640 · md 768 · lg 1024 · xl 1280 · 2xl 1536
Sidebar navapp-sidebar
≥ lg (1024): expanded; ≥ md (768): collapsible icon rail.
< md (768): collapses into a drawer behind a hamburger; scrim closes it.
Data table.tbl
≥ md: full table with horizontal scroll if needed.
< md: collapse to card-per-row OR keep the table inside overflow-x: auto. Never crush cells.
Page header actions.page-header-actions
≥ md: actions row aligned right.
< md: collapse secondary actions into an overflow menu; primary stays visible.
Form layout.form-section
≥ md: two-column grid (meta / fields).
< md: stack to single column; meta becomes a small header above its fields.
Modal / Drawer.modal · .drawer
≥ md: centered modal / right-side drawer at defined widths.
< md: bottom-sheet drawer or full-screen modal; never a 320 px box on a 360 px screen.
Touch targets--size-md-h
Pointer: coarse · auto-promotes md (36) → lg (44). No code change required.
Manually re-sizing controls per breakpoint — the media query covers it.
05 — Microcopy

Words are atoms too #microcopy

The fastest way to make a system feel cheap is generic copy. Specific verbs, honest errors, sentence case.

Button labelsverb · object
Save changesspecific verb + object
Confirms what will happen when pressed. "Send invite", "Publish update", "Delete project".
"OK", "Submit", "Done" — they don't tell the user what the button does.
Cancel / Discardthe escape
Pairs with a primary action. "Discard" when changes are lost; "Cancel" when nothing was done.
"Close" or "Nope" — too informal or unclear.
Sentence caseFirst word capitalized only
Buttons, titles, menu items, headings — everywhere except proper nouns.
Title Case — looks dated and inflated. ALL CAPS — looks shouty (overline tokens already handle it where needed).
Errorswhat + why + how to fix
"Enter a valid email"specific + actionable
Tells the user what's wrong AND what to do. Add a hint when the rule is non-obvious.
"Invalid input" or "Error 422" — the user can't fix what they don't understand.
"We couldn't save your changes"honest + first person
System errors say "we", not "you". Pair with a retry action and a way out (contact support).
"Something went wrong" with no detail, no retry, no context.
Trace IDs for 5xxhex string in monospace
Server errors that go to your logs. Lets users include it when contacting support.
Burying the trace ID in a network tab. Surface it tastefully.
Empty statesguide, don't apologize
"Create your first project"primary action in the copy
First-use. Explain what the thing is for, then point at the action.
"No projects" with no path forward. "Nothing to see here" — patronizing.
"No results for 'fnordling'"echo the query
Search empties. Offer to clear filters / widen scope. Echoing the query reassures the user the search ran.
A blank screen. A spinner that resolved to nothing without explanation.
Loading-state copyverb + ellipsis
"Saving…"specific gerund
Says what the system is doing right now. "Sending…", "Generating…", "Connecting…".
"Please wait" or "Loading…" — same words for every state, the user learns nothing.
Replace, don't appendon a button
Button label SWAPS — "Save" → "Saving…" → "Saved" — so the same control teaches the user what's happening.
Adding a spinner next to an unchanged label. Less information, same button area.
Numbers · dates · currencylocale-aware, never ambiguous
Large numbersthousands separator + tabular-nums
24,832 · 1,248,300 · $248,932. Use font-variant-numeric: tabular-nums wherever digits stack vertically (tables, KPIs).
24832 (unreadable). Mixing proportional digits with stacked values.
Abbreviation rulesk, M, B
24.8k · 1.2M · 3.4B for headline KPIs and tight chrome. One decimal max.
Mixing abbreviated and full forms in the same table column.
DatesMar 14, 2026 · 14 Mar 2026 — never 03/04/2026
Spell the month when space allows; ISO (2026-03-14) for system surfaces and CSVs. Relative ("2 hours ago", "Yesterday") inside the recency window.
"03/04/2026" — ambiguous across locales. Burying the year for dates in different calendar years.
Currencysymbol + ISO when ambiguous
$24.50 in a US-only context · $24.50 USD when other currencies appear nearby. Always 2 decimal places for fiat, even at whole values ($24.00).
Mixing "$" without context when supporting multiple currencies. Dropping decimals at zero ("$24").
Confirmationsname the consequence
"Delete project 'Onboarding v2'?"include the target
Destructive modals — name the thing being acted on so the user can sanity-check.
"Are you sure?" — answers nothing. Especially bad for delete actions.

Lookbook complete.

Eighteen chapters — Approach at the front, System at the spine, Brand and Craft layered above, Outward and Reference closing.

The contract is the token names. The values are the skin. Components reference tokens only — and they're written to keep that promise across every variant, every state, every theme.

When an agent picks up this system: start at Foundations to confirm the tokens, browse Atoms and Molecules for the parts list, lift composition shapes from Organisms, copy from Auth / States as needed, and dial up Personality where it earns the room.
