Composed Recipe · List / index view · table-driven · one skin, five compositions

Same skin. Five ways to index.

Every frame wears the same neutral skin — off-white page, white cards with hairline borders, one restrained blue accent, system sans with tabular figures. What changes is purely composition and interaction: where filters live, how the table is shaped, how you select and page. Loading and empty states are covered across the set; the skin is the paint, the composition is the skeleton.

Composition 1
Toolbar-classic

PULLS — sidebar shell + toolbar (search, filter dropdowns, primary “New”) + sortable data table + shape badges + bulk-action bar + numbered pagination.  WHY — the canonical CRUD index: sortable columns and multi-select are the first things power users reach for, and the bulk bar appears only when a selection exists.

Composition 2
Filter-rail

PULLS — top-nav + left faceted filter rail (status checkboxes, date range, amount) + saved-view tabs + airy table (right-aligned tabular numerals) + removable applied-filter chips + “load more” with a skeleton-row loading state.  WHY — finance lists are explored by slicing; a persistent rail plus echoed chips keep the active query legible, and incremental load suits long ledgers.

Composition 3
Command / dense

PULLS — keyboard-first command + search bar (“/” hint) + ultra-dense table (13px, zebra-free) with sticky header + select-all + one inline-expanded row + column-settings popover + density toggle.  WHY — event triage lives on density and keyboard speed; sticky headers and a command bar keep hands off the mouse while inline expansion reveals detail without losing place.

Composition 4
Card-rows

PULLS — generous card-rows (avatar + title + meta + trailing status pill + kebab) instead of a grid table + segmented filter (All / Active / Archived) + inline-editable status pill + a friendly empty state.  WHY — people-centric lists read better as roomy rows than dense cells; an inline-editable pill makes the most common edit one tap, and the empty state keeps a sparse view encouraging.

Composition 5
Ledger

PULLS — content-first single column with generous whitespace + ruled rows grouped by section with subtotal rows + minimal toolbar (search + quiet sort dropdown) + classic prev/next pagination.  WHY — a statement meant to be read, not operated: section grouping with subtotals tells a financial story top-to-bottom, and the restrained toolbar keeps it document-like.

Skins & how to apply them

A skin is nothing more than a small set of color + font tokens. Pick ONE skin per product and apply it across whichever compositions you choose — the composition is the skeleton, the skin is the paint. Every composition above is drawn in the Neutral skin; swap the token row and the same skeletons render coherently in any of the others.
