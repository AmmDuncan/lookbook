# Evidence — Mobile (reflow grammar + mobile-native compositions) (P-MO calibration)

Method: studied 21 real **mobile** (iOS) screens on Mobbin across six composition classes — bottom-tab navigation, hamburger/drawer navigation, filter bottom sheets, bottom-sheet modals, mobile detail screens, mobile lists — read by **(a) craft to learn** and **(b) how the rules are applied** — where reality confirms a rule, calibrates a number, or reveals a desktop assumption that doesn't survive a 390px touch surface. Reading reality on the phone is what catches the over-strict desktop guess; the strongest calibrations below are the components that *don't exist on desktop* and the desktop rails/dialogs that real mobile UI **refuses** to cram in. 2026-05-29.

Screens: **Bottom-tab nav** — Glass (floating pill bar + separated `+`), Airbuds Widget (4 icon-only tabs), Attio (4 tabs w/ labels: Home/Search/Tasks/Notifications), Duolingo (5 tabs + `⋯` overflow). **Drawer nav** — DoorDash Dasher (8-item icon+label drawer over a map), GCOO (8-item right-side drawer), Forest (12-item left drawer w/ scrim). **Filter sheet** — Beli (Sort-by segmented + collapsible facets + `Clear all` / `Apply (3)`), Instagram (Sort & filter sheet + `Clear` / `View 26 products`), Mercury (checkable facet rows + `See Results` / `Clear Filters (4)`), eBay (`Selected (1)` chip + chip-group facets + `Clear all` / `Show results`). **Bottom-sheet modal** — Skip (Menu Categories picker + `Cancel`), Tinder (near-full-height "Add birth place" search sheet w/ `X`), eBay (About-this-item detail sheet w/ `X` + scrim), Revolut Business (reason picker, searchable, dark, drag-handle). **Mobile detail** — Viator (hero image → title → price/rating → sticky `From $25.65 \| Check availability` bar), Me+ (article → single sticky `+ Add to my routine` pill), Alma (recipe → macros → two sticky actions: ghost `Share` + primary `Track`), Keeta (item sheet → sticky `– 1 + \| Add to cart ₿48.00`). **Mobile list** — Todoist (search-first + scrollable filter-chip strip), Target (type picker, checkbox rows, sticky `See results`), Notion (search list + `Sort ▾` + `Add filter` + a quick-filter sheet).

## The tablet / medium band (~600–1024px) — the most-broken width
The Mobbin study above is **phone-only** (iOS, ~390px); Mobbin's mobile captures don't exercise the ~768–1024px tablet band, so P-MO-12 is calibrated from the content-driven-breakpoint principle (F51) + responsive practice rather than a tablet receipt — flagged honestly. The reasoning: every collapse in the table above (rail→sheet, top-primary→bottom-bar, nav→drawer, multi-col→single) is the *phone* endpoint of a transform that, applied to ~768px, would over-collapse — a 900px viewport does **not** want a single 320px column, a bottom sheet, or a hamburger when it has room for two columns, a top-of-content panel, and a condensed bar. The failure is real and ubiquitous precisely because teams test desktop + phone and let the tablet band fall through to whichever neighbour's CSS wins, yielding "desktop squeezed" (columns collide, prose > 75ch breaking F5) or "phone stretched" (one narrow column marooned in whitespace). F51 resolves it: a breakpoint lands where a *rule* breaks, and the rule that breaks at phone width breaks **differently and earlier** at tablet → the tablet band earns its own breakpoint + its own intermediate composition (3→2→1 columns, rail-to-top before rail-to-sheet, nav-condensed before nav-hamburger, grids stepped not snapped). Fed P-MO-12.

## The dynamic-generation lesson
Mobile is **not** "the desktop layout at 390px." Two things change. First, the **reflow grammar**: every desktop composition has a canonical mobile collapse — two-column detail → stacked single column with the rail's *primary* fact promoted to a sticky bar; list toolbar → condensed search + a filter sheet; dashboard table → cards or horizontal-scroll; pricing tiers → stacked, recommended first; checkout summary → a collapsible sticky total. Second, **mobile grows components desktop doesn't have**: the bottom tab bar, the slide-in drawer, the filter sheet, the bottom-sheet modal, the sticky thumb-zone action bar. The contextual picks are real: **tabs vs drawer** by destination count + frequency (3–5 flat/frequent → tabs; >5 or deep/infrequent → drawer); **partial vs full-height sheet** by content height; **sticky bar vs FAB** by whether the primary needs context (price) beside it. Getting these right is the proof the screen was reasoned for the thumb and the viewport, not shrunk from a desktop comp.

## Over-strict / wrong-rule catches (the strongest calibrations)
- **Duolingo's `⋯` More tab and Glass's separated `+`** showed that "3–5 tabs" isn't a hard cap to violate by cramming — the *overflow* destination folds into a More tab and a non-destination create action sits *apart*, so the five thumb targets stay ≥44px. Fed P-MO-06's overflow rule + "create-action isn't a tab."
- **No filter screen used a desktop rail.** Beli/Instagram/Mercury/eBay every one opened a *sheet* with a sticky Clear/Apply footer — the instinct to port the desktop left-rail filter into mobile is wrong. Fed P-MO-08 + the forbidden "desktop rail stuffed into 375px."
- **Every bottom sheet had a drag handle, a scrim, and a visible dismiss** (X/Cancel) — none were traps. Fed P-MO-09's hard requirement that a sheet is always dismissible, and the forbidden "bottom sheet with no dismiss."
- **The sticky-bar primary always carried its context** (Viator price, Keeta total+stepper, filter-sheet result count) and never the destructive action. Fed P-MO-10's "primary in the thumb bar with context; destructive away from it."

## Calibrations applied to patterns/mobile.md
1. **Mobile-first reflow + content parity** — affordances relocate, never `display:none` (P-MO-01, F50/F51).
2. **Per-archetype collapse recipes** — detail→stacked+sticky-bar, list→condensed+sheet, dashboard-table→cards/h-scroll, pricing→stacked-recommended-first, checkout→collapsible-sticky-total (P-MO-02/03/04/05).
3. **Bottom tab bar (3–5 flat/frequent) vs drawer (>5/deep) vs top-back-stack** — contextual; overflow→`⋯`, create-action sits apart (P-MO-06).
4. **Filter as a bottom sheet** with collapsible facets + sticky `Clear` / `Apply (N)` footer, never a rail (P-MO-08).
5. **Modal → partial vs full-height bottom sheet** by content; drag handle + scrim + dismiss always (P-MO-09).
6. **Sticky thumb-zone primary** (bar/FAB) with context on the left, one filled verb; destructive away from the thumb (P-MO-10).
7. **Touch targets ≥44px at every width**; overflow destinations before shrinking them (P-MO-07, F52).
