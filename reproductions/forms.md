## Why a specimen sheet, not a single reproduced screen

A real form screenshot can never show the full state matrix at once — you can't photograph focus-visible *and* error *and* loading *and* disabled simultaneously, and the "no focus states" failure is precisely a state a still of a resting form doesn't reveal. So this is a **living style-guide surface** in two parts: (1) one believable *in-context* form that proves the voice + composition + placement, and (2) a *state matrix* that walks each control across its seven states with a dedicated FOCUS column. Both are rendered truth — the cookbook can point at a real cell for every state instead of asserting one in prose.

## The decisions I extracted (not traced)

1. **Focus is a real, painted state on every control — `:focus` for text fields, `:focus-visible` for buttons & controls.** Text fields show the ring on click-to-type (`:focus`); buttons, checkboxes, radios, toggles, segments, and combobox options show it on keyboard focus only (`:focus-visible`), so a mouse click doesn't flash a ring. The load-bearing indicator is a **solid mint border / 2px outline** (12.4:1 vs the page — clears 3:1 with enormous margin); a low-alpha mint halo only supplements it. This is the whole reason the file exists, so it is enforced — 0 elements fall back to the native ring.
2. **Error REPLACES help, never stacks.** Help sits below the control in `--faint`; on error it is swapped out for the message in `--neg`, prefixed with a small alert glyph, and the control gets a red border + a faint red wash + an in-field error icon (the Hashnode/Jasper/Substack/Salesforce pattern). One message slot, two contents — not a help line with an error line appended.
3. **Validate on blur, not per keystroke.** The in-context subdomain errs only after the field is left (the slug had a capital letter). Per-keystroke validation punishes a half-typed value; blur is the honest moment to judge a field complete.
4. **`*` for required, the word "optional" for optional — never both.** Required is a scarce mint `*` on the label; optional is said in mono words on the right. A form that marks every field one way or the other is marking nothing.
5. **Character counter is tabular and forgiving.** The textarea counter is `tabular-nums` (so it doesn't jitter as digits change), pinned bottom-right, and turns `--neg` on overflow showing the overage (`+9`) rather than hard-blocking the keystroke (the X pattern). Over-limit is an error state, not a wall.
6. **Server-search is the default for any list that grows from a backend.** The combobox searches a debounced term server-side and its popover carries a real **loading row** (spinner + "Searching the directory…"), a selected-option resolution, and an empty state — *not* a `page_size: 200` dump filtered on the client. The closed/searching/empty states are all shown. (This is the picker discipline a real product needs; a bounded set gets the native `select` instead, stated in the select track.)
7. **Three-tier button hierarchy, accent stays scarce.** Exactly one primary per view, filled **near-white (`--text`), never the accent** — the mint is reserved for focus/selected/on, so a primary button doesn't spend it. Secondary is bordered; tertiary is ghost text. Loading disables and swaps a spinner in while keeping the label ("Creating…").
8. **Label-above for entry fields, label-left for preference rows.** A value you *type* gets its label stacked above (P-F-06); a setting you *flip* (a toggle, an immediate-effect switch) gets a label-left row with a description (the Linear/settings grammar). The control's job decides the layout.
9. **Toggle vs checkbox is a submit question.** Toggle = takes effect immediately (no Save). Checkbox = submitted with the form. The two are not interchangeable skins; the matrix states this in the toggle track.
10. **Disabled is one defined treatment.** Every disabled control resolves to the same encoding (a class, not an inline `opacity` one-off): a darker surface, a dashed-flat border, dimmed text — so "disabled" reads identically across text, select, checkbox, radio, toggle, and segmented.

## Where the prior library was SILENT (the distillable)

1. **No recipe owned the control inventory or the state matrix.** `settings-page` shows *some* controls in *their resting state*; nothing walked text/select/combobox/textarea/checkbox/radio/toggle/segmented/button across default·hover·focus·active·disabled·error·loading, and nothing made focus a first-class column. → **cookbook: `cookbooks/forms.md`** — the input furniture as a recipe, with the state matrix and the focus discipline as its spine. `atom-field` / `recipe-form` are now COVERED by it, not the settings/modal stand-ins.

## The traps (each a critic finding, fixed)

- **"A state that doesn't read is a missing state."** The first cut's Default / Hover / Filled text-field cells were all *filled with a value* and the hover/active deltas were 1.04–1.25:1 luminance steps — invisible in a still. A state matrix whose entire selling point is completeness was failing to *show* the states. Fixed: Default is now an empty placeholder (vs a filled value), hover got a genuinely lighter border + surface lift, disabled got a **dashed** border + darker surface, and the primary **active** state got a real darker fill + inset shadow (a 1px `translateY` can't be photographed). Every labeled cell is now its own readable thing.
- **Status-cosplay creeps into your own chrome (AP28).** A mint status-dot beside the mono kicker ("● Float · form system") implied a live channel that doesn't exist — the exact tell `registers.md` warns slips into hand-built chrome. Removed. So did a decorative mint bullet prepended to each FOCUS label (the word is already mint — the dot was ornament spending a scarce-accent instance). The file's own rail says "one accent, nothing decorative"; the rework made that true.
- **One disabled treatment, one focus model.** Disabled had drifted into two encodings (inline `opacity` on some controls, a class on others); the segmented control had a *double* focus target (the group was focusable *and* each button was). Both unified — disabled is one class, the segment group is a plain button-group where each segment owns its ring, and the copy matches the markup.
